# Shared Antigravity Guard Core & Full Pi Behavioral Parity
Objective: Extract the Antigravity Guard runtime engine (live Hub version + fingerprints + shared `antigravity.json` config, multi-account `AccountStorageV4` pool + `hybrid` rotation, Strict Quota Guard + `daily -> autopush -> prod` failover/retries, permissive tool-schema sanitizer + disk `SignatureCache`) into `@benjamolina/antigravity-guard-core` via pure Move-and-Reexport facades (zero regressions in `@benjamolina/opencode-antigravity-guard`) and wire full 1:1 Guard parity into `@benjamolina/pi-antigravity-guard`, keeping `@benjamolina/pi-kit` decoupled.
Branch: `feat/pi-guard-phase5-multimodal-grounding` (Slice 5 of 5, stacked on `cf2598c`) | Delivery: `auto-chain` (`stacked-to-main`, ~350–400 authored lines/PR slice heuristic; cohesive core-extraction slices partitioned into sequential work-unit commits for RDD budget) | Runner: `npm test` (`vitest run`)

## Specs

- **S1 — Zero-regression Move-and-Reexport guarantee & decoupled `pi-kit` boundary**:
  - Fulfill `"llevarlo ese motor compartido a core y enchufarlo en pi-antigravity-guard, pero sin que lo que ya existe en  opencode-antigravity-guard haya bugs o deje de funcrinoar...."` and `"la idea era llevar todo lo de \"opencode-antigravity-guard\" tal cual a Pi para tener el mismo funcionamiento"`.
  - Preserve `@benjamolina/pi-kit` untouched and decoupled (dedicated solely to `cliproxyapi` and `9router`).
  - Keep every existing public function, type, constant, and on-disk contract (`AccountStorageV4` in `antigravity-accounts.json` and `antigravity.json`) in `src/` 100% backward-compatible via re-export/delegation facades so all existing OpenCode tests pass unchanged.
- **S2 — Phase 1: Shared `antigravity.json` cascade loader, live Hub version fetcher, & device `Fingerprint` in `core` + `pi`**:
  - Implement zero-dependency shared primitives in `packages/core`:
    1. `version.ts`: `createAntigravityVersionState` (`getVersion`, `setVersion` with `>= 2.9.1` floor check, never locking out later valid updates) and `fetchAntigravityHubVersion` (`latest-arm64-mac.yml`, `"User-Agent": "electron-builder"`, `"Cache-Control": "no-cache"`, 5s timeout).
    2. `fingerprint.ts`: `Fingerprint`, `FingerprintVersion`, `ClientMetadata`, `MAX_FINGERPRINT_HISTORY`, `generateFingerprint`, `collectCurrentFingerprint`, `updateFingerprintVersion` (migrating `antigravity/hub/<ver>`, `antigravity/<ver>`, `antigravity/cli/<ver> (...)`, and browser `Antigravity/<ver>` shapes with `>= 2.9.1` floor validation), `buildFingerprintHeaders`, and `createSessionFingerprintStore`.
    3. `config.ts`: `resolveSharedGuardPaths` and `loadSharedGuardConfig` implementing the Single Shared Pool with Cascade Fallback (`OPENCODE_CONFIG_DIR` -> `~/.config/opencode/{antigravity.json,antigravity-accounts.json}` when OpenCode directory/files exist -> `~/.pi/agent/{antigravity.json,antigravity-accounts.json}` standalone fallback, plus `<cwd>/.opencode/antigravity.json` and `<cwd>/.pi/antigravity.json` project overrides).
  - Delegate `src/constants.ts`, `src/plugin/version.ts`, and `src/plugin/fingerprint.ts` to `@benjamolina/antigravity-guard-core` with zero behavioral or signature drift.
  - Wire `packages/pi` (`extension.ts`, `provider.ts`, `stream.ts`, `project.ts`) to use shared `PiGuardRuntime` (`session_start` live Hub version refresh, session `Fingerprint` `User-Agent` migration, shared `antigravity.json` config loading including `request_jitter_max_ms` and `soft_quota_threshold_percent`) without altering synchronous provider registration or unit-test `fetch` counts when `session_start` is not fired.
- **S3 — Phase 2: Shared Multi-Account Pool (`AccountStorageV4` + lockfile) & `hybrid` Rotation in `core` + `pi`**:
  - Extract multi-account storage (`antigravity-accounts.json` v1→v4 migration, multi-process lockfile, `0600` permissions, email deduplication), `HealthScoreTracker`, `TokenBucketTracker`, `AccountManager` (`hybrid`/`sticky`/`round-robin`, `pid_offset_enabled`, proactive refresh, `invalid_grant` eviction, `403 validation_required` quarantine) to `packages/core`.
  - Wire `packages/pi` to use the cascade-resolved shared `antigravity-accounts.json` pool (with automatic non-destructive fallback/import from `~/.pi/agent/auth.json` on standalone Pi setups) and expose `/antigravity-accounts` and `/antigravity-quota` commands in Pi.
- **S4 — Phase 3: Strict Quota Guard + `daily -> autopush -> prod` Endpoint Failover & `429/503/529` Retries**:
  - Extract `quota.ts` (`fetchAvailableModels` / `retrieveUserQuota`, `classifyQuotaGroup` for Gemini 4 / Gemini 3 / Claude, `isOverSoftQuotaThreshold` strict reset-time lock) and resilient transport helpers (`ANTIGRAVITY_ENDPOINT_FALLBACKS`, `RetryInfo` parser, jittered exponential backoff, automatic account switch on soft-quota or rate-limit) to `packages/core` and wire into `packages/pi/src/stream.ts`.
- **S5 — Phase 4 & Phase 5: Permissive Tool-Schema Sanitizer, Disk `SignatureCache`, PDFs, `google_search`, & Variants**:
  - Phase 4: Extract `cleanJSONSchemaForAntigravity` / `toGeminiSchema` (`$ref`, `anyOf`/`oneOf`/`allOf`, `const` -> `enum`, constraints in `description`, empty-object `_placeholder`) and disk `SignatureCache` + `skip_thought_signature_validator` to `packages/core` and wire into `packages/pi/src/tool-schema.ts` and `context.ts`.
  - Phase 5: Add `application/pdf` input support, `google_search` grounding + `-sonar`/`-tiered` catalog variants, dynamic model discovery option, and synchronize `packages/pi/README.md` + `packages/pi/evidence/`.
